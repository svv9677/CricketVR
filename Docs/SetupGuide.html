Start here — MCP for Unity

This is the bridge that lets Claude Code drive the Unity Editor directly: create GameObjects, edit scripts, read the console, run play mode. Most of the recent debugging was done through it, so it is worth setting up properly rather than treating it as optional.

Repository github.com/CoplayDev/unity-mcp

MCP for Unity by Coplay. We are pinned to v10.2.0.

 Documentation coplaydev.github.io/unity-mcp

Read this if a step below does not match what you see.
Good news

The Unity half is already vendored into our repo at Packages/com.coplaydev.unity-mcp/ — 708 files, committed. You do not install it from the Package Manager. When you open the project it is simply there. You only have to set up the server half, in step 5.

What you need before you start

  • Disk space: about 12 GB free. The clone is roughly 800 MB, and Unity then generates a Library/ folder that reaches 8–9 GB.
  • A Unity account with a free Personal licence.
  • A GitHub account. The repo is public so you can clone without one, but you need Dad to add you as a collaborator before you can push.
  • Git. Already on macOS via Xcode command line tools; on Windows install Git for Windows.
  • Claude Code, signed in.
  • A Quest headset with developer mode enabled, and a USB-C cable that carries data (not a charge-only one).
Not needed

We do not use Git LFS. The .gitattributes file has LFS rules in it but they are all commented out on purpose. Do not run git lfs install in this repo — it would rewrite how the binary assets are stored and break the clone for everyone else.

Setup

1

Install Unity Hub and the exact Editor version

Get Unity Hub from unity.com/download, sign in, and activate a free Personal licence.

Then install Unity 6000.3.24f1 — that exact build. A different patch version will upgrade the project files on open, and the diff lands on everyone else.

When the Hub asks which modules to add, tick:

  • Android Build Support
  • OpenJDK (nested under Android Build Support)
  • Android SDK & NDK Tools (also nested)

Both nested boxes matter. Without them the Android platform shows up greyed out and you cannot build to the headset.

If the Hub does not offer 6000.3.24f1 in its list, use the direct archive link:

unityhub://6000.3.24f1/4e7b9b5b6244
2

Clone the repo

Pick a folder without spaces or iCloud sync in the path. Unity and the MCP server both behave better that way.

git clone https://github.com/svv9677/CricketVR.git
cd CricketVR

This pulls about 760 MB of packed history, so give it a few minutes. Everything you need is in that one clone — no submodules, no LFS fetch, no separate asset download.

Check you landed on the right commit:

git log --oneline -3
git status

git status should say the working tree is clean. If it lists modified files straight after a fresh clone, stop and ask Dad before opening Unity.

3

Open the project in Unity

In Unity Hub choose Add → Add project from disk and pick the CricketVR folder. Confirm the Hub shows 6000.3.24f1 next to it, then open it.

This takes a while

The first import compiles every shader and reimports every texture from scratch. Expect 20–40 minutes depending on your machine, and a progress bar that looks stuck more than once. Let it finish. Quitting partway through leaves a corrupt Library/ and you have to delete it and start over.

When it settles, open Assets/Scenes/CricketVR.unity. That is the only scene enabled in the build — Nets, Splash and BatOffsetDebug are side scenes for testing.

4

Install uv, which runs the MCP server

The MCP server is a Python program, launched through uvx. You do not install the server yourself — uvx fetches and caches the pinned version on first run.

macOS

brew install uv
uvx --version

Windows (PowerShell)

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
uvx --version

If uvx --version prints a version number you are done with this step.

5

Connect Claude Code to the Unity Editor

With the project open in Unity, go to Window → MCP for Unity → Toggle MCP Window (Cmd+Shift+M on Mac, Ctrl+Shift+M on Windows).

Find Claude Code in the client list and press Configure. That registers the server for you by running claude mcp add behind the scenes. This is the path to prefer — it fills in the right paths for your machine.

If the button fails, register it by hand from inside the project folder:

claude mcp add UnityMCP -- uvx --from mcpforunityserver==10.2.0 mcp-for-unity

Then restart Claude Code and confirm the connection:

claude mcp list
How it works

Unity has to be open for any of the MCP tools to respond — the server talks to the running Editor, not to the files on disk. If Claude says it cannot reach Unity, the usual cause is that the Editor is closed, mid-compile, or showing a modal dialog.

6

Set up adb for the headset

You need adb to install builds and to read logs. Unity already installed it with the Android SDK module, so you just have to put it on your PATH.

# macOS, if you also have Android Studio installed
export PATH="$PATH:$HOME/Library/Android/sdk/platform-tools"
adb devices

Otherwise the copy bundled with Unity lives under the Editor install, at PlaybackEngines/AndroidPlayer/SDK/platform-tools/.

Put the headset on and accept the Allow USB debugging prompt — it appears inside the headset, not on your screen, and it is easy to miss. Then adb devices should list one device as device rather than unauthorized.

Run through these before you change anything. If one fails, fix it now rather than after you have edited a scene.

Switching to Android

If Android is not already the active platform, switching costs another long reimport — every texture gets recompressed to ASTC. Start it and go do something else.

Building to the Quest

Enable developer mode on the headset first, through the Meta Horizon phone app: open the app, select your headset, then Headset settings → Developer mode. You need a Meta developer account, which is free but does require a verified organisation.

Then in Unity: File → Build Profiles, platform Android, and Build And Run with the headset plugged in.

These are already committed in ProjectSettings/, so they should be correct on a fresh clone. They are listed here so you can tell when something has drifted.

Do not commit

ProjectSettings/ProjectSettings.asset has a preloadedAssets list that Unity fills in and empties around every build. It is supposed to be empty at rest. If a build leaves entries in it, revert that file rather than committing it.

Reading logs from the headset

The game mirrors every Debug.Log onto a board inside the world, which is handy while playing but unreadable in a video capture. For anything real, use logcat.

Start the capture before you run the build. The Quest's log buffer is small and only holds a couple of minutes by default, so asking for values after the fact gets you nothing.

export PATH="$PATH:$HOME/Library/Android/sdk/platform-tools"
adb logcat -G 64M && adb logcat -c
adb logcat -v time -s Unity:I > dev.txt

-s Unity:I filters out the constant Meta tracking and camera chatter, leaving just our own logging. -G 64M grows the buffer, and it has to be set before the run.

If adb devices comes back empty even though the cable is in, the daemon is usually stale:

adb kill-server && adb start-server && adb devices

Known oddities — not your fault

These are all expected. Knowing about them saves you chasing ghosts.

Four missing script references

A project-wide scan turns up four unresolvable script GUIDs: two in Steyn.controller, one across five leftover Oculus sample scenes, and one across nine DebugUI prefabs. All four pre-date the revival work. Four is the expected count — worry only if it goes up after something you did.

Boundary detection does not exist yet

There is no boundary object in the scene, so fours and sixes are never detected and the fielder intercept code throws on every hit. It is issue 6 in the backlog and is waiting on a decision about the boundary radius.

Scoring is time-based

Runs are worked out from how many seconds pass between the bat hitting the ball and a fielder reaching it, not from where the ball actually goes. Under two seconds is a dot ball, over eleven is four runs. It is a placeholder from the original build, not a bug.

The vendored Oculus SDK is ancient and that is fine

Assets/Oculus is a 2021-era copy of the old Oculus Integration package. It compiles cleanly under Unity 6.3 and we deliberately kept it rather than migrating to the Meta XR SDK. Do not "helpfully" update it.

Working in the repo

  • Pull before you start, every time. Unity scene and prefab files do not merge — .gitattributes marks them -merge on purpose. If you and Dad both edit CricketVR.unity, one of you loses the work. Say what you are opening.
  • Never commit Library/, Temp/, Builds/ or Logs/. They are gitignored already; do not force-add them.
  • Always commit the .meta file next to any asset you add. Unity tracks every asset by the GUID inside its .meta, and a missing one breaks the reference for everyone else.
  • Rename and move assets from inside Unity, not in Finder or Explorer, so the .meta travels with the file.
  • Ask Dad before pushing to master. There is a pre-revival tag marking the pre-Unity-6 state if you ever need to look back.
